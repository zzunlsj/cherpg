## 1. 프로젝트 목표와 최종 방향

### 1.1 게임 정체성
체스의 **기물별 행마**를 게임 세계의 공간 법칙으로 받아들이는 스토리 중심 RPG. 처음에는 브라우저에서 **턴제·격자 전술 게임**으로 제작하고 이후 **Godot 기반 PC용 3D 오픈월드, 3인칭 폰 조작**으로 방향을 확장했다. 8×8 보드에 제한하지 않으며 지역, 장애물, 회전 장치, 성장, 장비, 캐릭터 대화, 분기형 승진이 게임 핵심이다.

**주제 문장 [정사]:** “성장은 다른 기물이 되는 것이 아니라, 자신의 방향을 스스로 선택하는 법을 배우는 것이다.” 주인공은 폰에서 벗어나는 것이 자유라고 생각하지만 마지막에는 폰인 채 자신의 ‘앞’을 스스로 결정한다. 최종 대사: **“폰. 다만, 어디로 갈지는 제가 정합니다.”**

### 1.2 채택된 제작 방향
- **게임:** 초기 웹 알파 → 장기적으로 Godot 3D. 모바일 플랫폼은 고려하지 않음.
- **3D 캐릭터:** Blender 모델링·모듈화 → GLB 내보내기 → Godot에서 조립, 리깅·LOD·상호작용 검증.
- **세계:** 중세풍 왕국. 마법 같은 임의 기술보다는 판면공학, 회전판, 고대 석조·청동 시설의 논리로 시각화.
- **개발 방식:** 캐릭터, 보드 전투, 맵·지형, 타임라인을 독립적으로 설계하고 점진적으로 결합.
- **검증 원칙:** 코드/파일을 생성했다는 사실과 실제 실행, 화면 검수, 사용자 최종 승인 여부는 별개의 단계.

## 2. 세계관 정사: 기초 물리법칙

### 2.1 판면과 행마
[정사] 세계에는 보이지 않는 격자인 **판면**이 있다. 기물은 칸 내부에서 자세·소규모 위치를 바꿀 수 있으나, **다른 칸으로 넘어가는 실제 공간 이동은 행마**의 지배를 받는다. 행마는 단순 신체 능력이 아니라 판세계의 공간 규칙이다. 기물형(폰·룩·비숍·나이트·퀸·킹)은 몸, 행마식, 사회적 역할이 서로 영향을 주고받지만 인격이나 법적 운명을 결정하지 않는다.

- **신체 방향**과 **행마 기준 방향**은 별개다. 폰은 몸을 돌려 보아도 자신의 행마 기준 ‘앞’이 저절로 바뀌지 않는다.
- 현대 폰의 기준 방향은 외부의 **방향 앵커**를 통해 갱신된다. 고정 회전 타일과 휴대용 방향 전환 장치는 이런 외부 갱신 장치다.
- **회전 타일:** 폰 등이 올라선 칸의 기준 방향을 외부에서 바꾼다. 90°/180° 회전은 수송·군사·일상 기반 시설의 핵심이다.
- **아버지의 휴대 장치:** 현재 발밑 타일에 앵커를 내리고 단단히 고정한 뒤 **타일은 그대로 두고 착용자의 몸만 회전**시킨다. 최종적으로 이 기계적 보조와 폰 자신의 자율 방향 전환을 명확히 구별해야 한다.
- **이동 행마 / 공격 행마 / 잡기 / 스킬 / 행동력**은 구별하여 설계한다. 턴제 게임 표현은 세계관상의 불연속 시간 물리법칙과 동일시하지 않는다.

### 2.2 왕정석과 규칙의 진실
[정사] 최초의 판에서 발견한 **행마원석**은 다양한 행마의 가능성과 기록을 보존한다. **왕정석**은 행마를 최초로 창조한 돌이 아니라, 전쟁 종결 후 행마원석에 통일 규칙 관리장치와 중계망을 결합한 세계 규모 **활성/봉인/동기화 체계**다. 표준에서 제외된 행마는 삭제되지 않고 봉인되어 남는다. 비표준 행마와 봉인 행마는 같은 개념이 아니다. 왕정석 붕괴 뒤에도 세계의 모든 행마가 즉시 소멸하지는 않는다.

주인공에게 들어온 파편은 여행 중 겪은 서로 다른 행마를 기록한다. 이 기록은 **예언받은 선택자**라는 운명보다 **지표 운반자/수집 시스템**과 연결되며, 최종적으로 봉인된 폰의 **자율 행마 ‘방향 전환’**을 일깨우는 조건이 된다.

### 2.3 역사적 흐름
1. **원초판 시대:** 「최초의 수를 둔 자」가 최초의 두 칸과 판을 만들고 기물보다 먼저 행마를 부여했다는 전승.
2. **지역 규칙 시대:** 같은 기물도 지역에 따라 방향·승진·이동 체계가 다양.
3. **회전망 확산기:** 폰의 이동 제약을 줄이려 회전 타일과 물류망이 보급.
4. **갈라진 판 전쟁:** 규칙 권한·정치·전쟁이 복합적으로 맞물린 83년의 전쟁. 회전판 파괴는 대표적인 대폰 전술.
5. **대동 전환기:** 공동 조사대가 최초의 판과 행마원석 발견, 통일 행마 계획 수립. **대동기** 때 일부 규칙을 세계 표준으로 동기화.
6. **왕국 통합 및 대안정기:** 레갈리아 질서, 정칙원, 표준 승진 제도와 공식 역사 강화.
7. **균열 전조기 및 본편:** 레갈리아 재건 실험과 왕정석 붕괴, 지표 운반자 수집, 봉인 규칙의 진실을 추적.

**창조 전설의 핵심 구절:** “나는 길을 만들었지만, 그 길의 끝까지 정하지는 않았다.” 후대의 통제 중심 해석과 실제 가능성을 대비한다.

### 2.4 사회 제도와 문명
[정사] 폰은 노동·수송·보병 분야에서 흔하고, 승진 가능성은 사회적 지위와 기물형 사이의 긴장을 만든다. 승진은 칭호 변경이 아니라 행마식과 몸을 실제로 바꾸는 변환이다. 킹형과 왕위는 동일 개념이 아니다. 폰의 높은 승진 가변성은 강점이자 통제 대상이 된다.

세계관 도감에는 **사회·직업·계층/법과 비표준 행마/승진과 안전/종교·정칙 신앙/전쟁과 전술/중세 경제·통화·수송/판면공학·중계기/다른 판세계/정보 비공개**까지 세부 규칙이 작성되어 있다. 이 통합 문서는 17개 장의 의사결정과 관련 개발 이력을 연결하는 색인 및 요약이며, 수백 쪽 분량의 원문 전체를 1:1 전재한 문서는 아니다.

## 3. 스토리, 캐릭터, 진영과 결말 (스포일러)

### 3.1 프롤로그와 주인공
[정사] 주인공은 **회전로 마을 출신의 폰**. 어린 시절 폭우·산사태로 회전 타일이 멈춘 사고에서 아버지가 수동 회전으로 주민을 대피시키다 돌아오지 못한다. 그는 다른 기물이 되어야만 자유로워진다고 믿어 군에 들어갔다. 왕정석 이상 이후 고향으로 돌아와, 오랫동안 닫혀 있던 아버지의 작업실에 들어가 **미완성 휴대용 방향 전환 장치**를 완성한다. 이후 왕정석 파편을 획득하고, 왕국군과 정칙원의 회수 대상으로 떠오른다.

### 3.4 승진/성장 정사
**첫 분기:** 성역→비숍(다른 관점), 대초원→나이트(장애물 도약), 숨은 지하 회전로→베롤리나 폰(폰 자체의 변형).

**상위 진로:** 기본 공통 대안은 룩. 비숍 계통은 **불안정한 퀸**, 나이트 계통은 **드래곤**, 두 계통을 다시 잇는 특수 조건은 **아치비숍**. **베롤리나 폰**은 형태를 유지한 채 변형했으므로 이후 여러 승진 제안을 계속 받을 수 있다. 모두 거절하면 **최대 2칸 이동하는 강화 폰**의 기회를 얻는다. 2칸 이동의 매턴 가능 여부·통과 조건 등 세부 밸런스는 미정이다. **룩은 모든 경우에 강제되는 중간 단계가 아니다.**

**메가 체스트론:** 전쟁 말기에 여러 기물 모듈을 하나로 연결한 단 한 기의 거대한 중앙 통제 병기. 룩 돌진/방어→비숍 포격→나이트 도약→퀸 다행마 전환 등의 국면을 갖고, 본편 철의 묘지에서 봉인 해제. 완전 파괴보다 중앙 연결 중단으로 정지시키는 결말 방향. “모든 움직임이 가능하나 선택권은 없다”는 주제상의 반례다.

### 3.5 최종 반전과 엔딩
1. 오르렌이 **다른 판세계(증강 체스 세계)**의 카드 **「일장춘몽」**을 사용한다.
2. 플레이어가 쌓은 **모든 승진·베롤리나 변형·2칸 강화**까지 사라져 완전한 **기본 폰**으로 되돌아간다. 경험·전투 기술의 기억은 남는다.
3. 주인공은 아버지의 휴대용 장치를 다시 꺼내지만, 오르렌은 고대 대폰 전술처럼 방향을 뒤집은 뒤 **회전축과 앵커**를 파괴한다.
4. 왕정석 파편이 여행 중 행마 기록을 재생, 외부 기계가 없는 상태에서 폰 자신의 의지를 인식해 봉인 행마 **「방향 전환」**을 개방한다.
5. 최종 2단계에서 주인공은 **폰 상태를 유지**하며 방향 전환과 축적된 기술로 싸운다. 최초 각성에는 **앵커 하강·회전 타일·‘철컥’ 소리 모두 없어야 한다.**
6. 엔딩에서는 왕정석을 어떻게 재구성할지가 자동 정답으로 제시되지 않는다. 사방으로 갈라진 길에서 플레이어가 스스로 방향을 선택하고 **「세계 01 끝」**.

**확정된 전투 방향 전환 스킬 초안:** 제자리에서 상·하·좌·우 중 ‘앞’을 재설정해 기본 전진·대각선 공격 방향을 함께 회전, 행동력 1, 재사용 대기 1. 밸런스 구현 때 재검토 가능.

### 3.6 스포일러 관리
공개용 소개에서는 **폰의 자유에 관한 위화감만 암시**하고 왕정석의 기원, 지표 운반자, 일장춘몽, 바렌의 진실, 최종 각성을 직접 공개하지 않는다. 원초 기록·아버지의 수첩·낡은 시설·방향 기록·「철컥」 소리·다른 방향의 폰 벽화를 단계적 복선으로 쓴다. 설정집의 **작가용 정사**와 플레이어에게 **실제로 알려주는 정보**를 엄격히 분리한다.

## 4. 브라우저 2D 알파 개발 이력

### 4.1 초기 알파와 UI
[과거 산출물] PC 브라우저 플레이용 로비·보드·스토리·AI·개발자 모드를 확장. 초기 로비 두 안을 비교해 최종 **1안**을 선택했고, 100% 배율 선명도 문제를 조정했다. 메인에는 **이어서 하기 / 새 게임 / 불러오기 / 설정** 네 버튼. 보드 색을 녹색 계열로 정리하고 턴 상자·이동 상자 충돌, 사이드바 스크롤, 자동 스크롤 튐 등을 반복 수정했다.

### 4.2 전투와 입력
- **플레이어/적 턴 교대**, 체스식 합법 이동, 경로 차단, 적 AI의 잡기 우선/접근 행동, 승리·패배·재시도·다음 스테이지.
- **클릭과 드래그 이동을 병행**. Shift를 누르면 적 전체의 공격 범위를 표시.
- 기보를 왼쪽 세로 리스트로 표시. 항목 클릭 시 **과거 상태 읽기 전용 재생**, 처음/이전/다음/현재 이동. 과거 상태는 색이 바래 보이고 LIVE와 구별.
- 적 행동 지연과 속도 조정, 스포트라이트·시간 역행→암막 전환, UI 톤 통일.
- 잡기 연출의 과도한 확대 제거. **충돌 후 반대 방향으로 파편이 밀리고 낙하하며, 약 1초 후 사라지는** 방향으로 조정. 아군 사망 파편 효과도 적과 통일하고 패배 화면은 마지막 파편 연출 종료 후 표시.
- **체력바는 기물 바로 위 고정**. 과거 시점에서는 시각·입력 구분이 무너지지 않게 유지.

### 4.3 기능·기물 설계
- 보드 크기는 8×8에 고정하지 않고 벽·숲·물·얼음·용암·출구·상자·스위치·NPC로 확장.
- 체력/공격/방어/장비/상태이상(Guard, Slow, Stun, Shield 등)과 행동력 계획. 체스식 일격 잡기와 RPG 데미지 방식은 별도 밸런스 검토 항목.
- **개발자 모드**: 불러오기 화면의 4번 슬롯과 연결된 보드 편집기(기물 배치·전투 테스트).
- 기물: Pawn, Knight, Bishop, Rook, Queen + 변형 **Xiangqihorse**(수정된 이동/공격 규칙), **Chariot**(정지 시 방어), **Sailboat**(물 타일 수송), Archbishop, Dragonbishop, Chancellor, Amazon 등.

- 초기 로드맵의 단순 **Pawn→Knight/Bishop→Rook→Queen** 트리와 이후 확정된 **서사 분기 트리**는 역사적으로 서로 다른 설계 단계다. **현재 서사 정사를 우선**한다.

## 5. Godot 3D 오픈월드 전환

### 5.1 기본 상호작용 [확정 요구]
- **Godot** 채택, PC 우선, **모바일 제외**.
- 3인칭에서 직접 폰을 조작. 단위 기준 **1타일=2m×2m**, 폰 키 **1.5~1.6m**(마을 JSON 값 1.55).
- 폰의 실제 행마 기준 이동은 **앞/뒤 중심**으로 제한하고 회전판이 방향을 바꾸는 핵심 메커니즘을 유지. 보통 자유 이동형 TPS처럼 임의 방향 이동을 허용하지 않는다.
- 실내, 문, 교량, 경사로, 계단, 수송시설과 지형 고저차에 행마 제약을 어떻게 접속하는지가 핵심 기술 과제.
- 2D 배치와 3D 지형/오브젝트 표시는 상호 대응해야 한다.

### 5.2 세계 전체 구조
[정사와 지도 초안 연결] 남서부 **회전로 마을·변경 검문선**에서 시작하여 **대초원 / 오래된 성역 / 지하 회전로**로 분기, **곧은 도시·왕실 요새·중앙 행정권**, 이후 **규칙 붕괴 지대·용의 능선·쌍행 성역**, 북부 **철의 묘지·빙결 중계기**, 심층 **원초 기록고·지표의 무덤·중앙관문·최초의 판**으로 연결한다. 지상 2D 지도에 보이지 않는 **지하/원초판 층위**를 별도 표현해야 한다.

[초안 파일] **chess-RPG-world-draft-7v.map.json**은 중세 지상 **16km×16km(256km²)의 임시 편집 작업면**, **12개 지역**, **1,361개 배치 객체**를 담는다. 이는 **세계관의 최종 확정 면적이 아니다**. 지도에는 산맥·숲·들·강/교량·마을·도시·검문선과 공학 시설을 배치했다. 대규모 지도와 각 마을/실내 미시 지도는 별도의 밀도로 관리한다.

**12개 편집 지역:** 01 회전로 마을, 02 변경 검문선, 03 대초원, 04 곧은 도시, 05 왕실 요새, 06 중앙 행정권, 07 오래된 성역, 08 규칙 붕괴 지대, 09 쌍행 성역, 10 용의 능선, 11 철의 묘지, 12 북부 빙결권·중계기. 이는 지상 편집용 구획이며 스토리의 모든 지하 구역을 포함한 전체 목록은 아니다.

### 5.3 회전로 마을 상세 설계
초기 마을은 집과 간격이 과밀·광대하다는 평가를 받아 **가구 수 약 1/3**, 생활권 축소, 집과 입구를 길에 밀착하는 방식으로 재구성. 고증 참고는 **Wharram Percy, Hangleton, Bayleaf** 등의 중세 농촌 구성 요소였으나 **완전한 역사 복원이 아닌 게임용 재구성**이다.

**필수 요소:** 주인공 집, 작은 교회, 여관, 수차 방앗간, 소수 농가, 작업장·창고·텃밭, 자연스러운 시냇물·언덕·울타리, 마을을 둘러싼 밀도 높은 숲. 길만 따라 **출입문이 있는 모든 건물에 접근 가능**, 건물 입구↔도로 간격 최소화. 기존 수레길은 제거하고 **서쪽 벌목 숲길**, **깊은 숲 진입로**, **변경 검문선/마을 바깥 출구**를 마련. 회전판끼리 겹치거나 붙지 않도록 하고, 도로 폭/회전판 폭의 충돌을 수정했다. 나무는 길·건축을 침범하지 않되 마을 외곽에 불규칙하게 배치한다.

[초안 파일] **chess-RPG-rotating-village-10v.map.json**은 별도 마을 편집 데이터다. map.width=320, depth=256, tileSize=2, pawnHeight=1.55; **총 400개 객체**(나무 326, 도로 16, 회전판 15, 건물 유형별 객체 등). 값들은 **해당 JSON의 편집 단위**이며 실제 Godot 월드 측량·충돌판정을 완료했다는 뜻은 아니다. 과거 세계 맵의 설명에는 마을 **640m×512m 편집 영역**이라는 별도 표기도 있다. 단위·좌표계를 정합해야 한다.

### 5.4 확장 순서
회전로 마을 → 변경 검문선까지의 현실적인 연결을 먼저 강화하고, 이어서 이웃 지역을 단계적으로 확장한다. 도로의 연결 가능성·울타리·강·경사·교량·실내 출입·회전판 충돌, 지표/지하 연결, 산악 지형을 **2D와 3D 양쪽에서 확인**할 것. 지금까지의 지도 JSON은 **배치 초안**이지 완성된 Godot 게임 씬이 아니다.

## 6. 월드·지도·시간선 에디터

### 6.1 과거 제작된 도구
[과거 산출물] **chess-RPG-map-editor-0.1.14v.html**이라는 브라우저 단일 HTML 에디터가 생성되었고, 지도 JSON의 읽기/쓰기·배치 편집·2D/3D 전환 기능이 구현된 코드가 존재한다. 다만 이 HTML은 **2026-10-12 현재 GitHub main의 파일 목록에는 없다.**

### 6.2 확정된 편집 개념
- **구역 기반 편집:** 큰 지도를 지역별로 나누고 구역 단위 잠금·선택·편집·확대. 객체의 위치, 크기, 높이, 종류, 상태와 지역 소속을 관리.
- **3D·2D 대응:** 평면 배치와 3D 시점의 동기화를 유지. 높이/건축/지형 편집이 엇나가지 않도록 일관된 좌표 기준 적용.
- **건축:** 문을 1개로 고정하지 않고 여러 개 추가. 일반문·미닫이문·차고지형 문 등 **문 종류**, 문 크기·위치·방향, 창호·계단·경사로를 편집.
- **선택/그룹:** 다중 선택한 객체의 시기·상태를 일괄 수정, 그룹 묶기·해제, 시간선에서 그룹을 **한 줄**로 처리.
- **시간선:** 비디오 편집기를 닮은 시기/클립 편집. 초기 마블 시각화에서 **직선·밧줄 꼬임·곡선 조정**으로 발전, 드래그로 분기/구간 길이 관리. **숨김은 단절 구간**으로 표현하고 정상/잔해/폐쇄 상태 등과 연결. 시간선 압축에 따른 부자연스러운 꺾임을 방지하고 용어 통일.
- **상태 재생:** 선택 시기의 구조물 상태·폐쇄 구역·파괴 잔해를 확인. 교차된 가닥 및 구간 연결은 실체 상태와 모순되지 않아야 함.
- **내보내기:** 게임 배치 JSON, 3D OBJ 시제품 등 도구 기능을 검증하고, **Godot 수입 파이프라인으로 이어지는 실제 사용 포맷**은 추가 결정.

**중요 경계:** 시각적 에디터 기능이 생겼다는 것과 Godot 게임 런타임 통합이 끝났다는 것은 다르다. 장시간 저장/불러오기, 대용량 지도 성능, 충돌/내비게이션, 시간선 브랜치 영속성은 별도 검증.

## 7. 캐릭터 일러스트·Blender 제작 이력 및 현재 리셋

### 7.1 원본 일러스트 우선 원칙 [확정 요구]
폰 주인공은 **실사 인간이 아니라 스타일화된 석조 폰 영웅**. **승인된 일러스트와 여러 방향 디자인 시트**가 모든 3D 조형의 원본. 과거 인간형에 가까운 얼굴 모델·기괴한 눈/입은 불합격으로 재작업을 지시했다. 일러스트에 없는 금색 균열, 과도한 장식, 헬멧 비대칭, 현실적 귀/구형 안구를 임의로 넣지 않는다.

2026-10-09~11 일러스트 검토에서는 여러 해부도/머리 분해도를 **작업 목록에서 폐기**하고, **22번 ‘폰 용사 머리 3파트 조립 설계도’, 26번 ‘폰 용사 전신 캐릭터 디자인 시트’, 27번 ‘폰 용사 전신 캐릭터 최종 디자인 시트’**를 보존 대상으로 명시했다. 별도로 기존 승인 **원본 일러스트 및 정면·측면·10방향 참조**의 효력도 유지된다. 이 항목은 **작업·선별 기록**이며 실제 이미지 파일이 현재 GitHub에 업로드되었다는 뜻은 아니다.

### 7.2 분리 가능한 머리의 3대 모듈
현재 보존된 기준: **docs/pawn_hero_modular_head_contract_v0012.md**.

1. **PART_01_HELMET:** 중심 폰 구슬을 가진 아이보리 석조 2단 실루엣. 밑면이 실제로 **비어 있는 중공 구조**, 좌우 대칭, 불필요한 중앙 장식 없음.
2. **PART_02_HAIR:** 실루엣에 맞는 밝은 조각층/갈래 형태 머리, 앞머리·옆·뒷머리를 모두 포함. 헬멧/얼굴 조각을 섞어 굽지 않음.
3. **PART_03_FACE:** 민머리 두개 형태, 뺨·각진 턱·목 연결. 얼굴 기본형, 좌우 귀, 눈의 평면 인레이, 눈썹, 코, 입은 **각각 탈착 가능한 하위 그룹**. 얼굴 기본형에 귀·코가 융합되지 않음.

모든 모듈은 조립 좌표·실제 스케일을 유지하며, 분해도용 이미지에 맞춘 가짜 크기 변경을 하지 않는다. 중립적인 표정과 일러스트의 얼굴 윤곽 유지. **0°/45°/90°/135°/180°/225°/270°/315° + 위·아래**의 직교 뷰를 활용하여 조립 정확도를 검사한다. 얼굴형, 재료감, 메시 밀도, 충돌 간격, GLB, Godot의 LOD·리깅을 별도 검수한다.

**추가 주의:** 대화상 요구에는 “안구·홍채·동공을 구체처럼 추가하지 말 것, 귀·코·눈 형태만”이 있다. 현재 계약서의 ‘flat eye inlays’는 스타일화된 **얇은 표면 표현**이지 실사형 눈알을 허용한다는 의미가 아니다.

## 12. 다음 작업 백로그: 우선순위와 완료 조건

### P0. 소스와 기준 복원
1. **승인된 폰 원본 일러스트·보존 디자인 시트(22·26·27 등)**를 references 경로에 **원본 해상도/방향 정보와 함께 저장**. 기존 대화의 시각 자료를 임의로 재생성해 승인본으로 바꿔치기하지 않는다.
2. 현재 main의 design contract와 이 문서가 모순 없는지 재검토하고, 정사 변경 사항은 날짜·근거를 함께 기록.
3. 이전 웹 알파 ZIP, 월드/마을 JSON, 에디터 HTML은 사용자 의사에 따라 별도 정식 소스 경로를 확정한 뒤 옮긴다. **현재 없는 파일을 이미 복원했다고 간주하지 않는다.**

### P1. 핵심 3D 캐릭터 하나를 합격시키기
1. 헬멧·머리카락·얼굴 3대 조립 파트와 독립 하위 요소의 **단일 스케일/좌표 기준**.
2. 일러스트와 10뷰 실루엣 대조, 헬멧 속 비어 있음·귀의 소속·눈의 평면 표현·중립 표정을 반복 확인.
3. 조립 정확도→메시·노멀·UV·재료→GLB→Godot 장면과 회전/애니메이션→다각도 실제 렌더 순서로 승인.
4. 사용자 승인 이전에는 ‘완성’ 또는 ‘최종 모델’로 선언하지 않음.

### P2. 3D 이동의 작은 검증 세계
**회전로 마을의 일부분과 연결 도로**에서 폰 전진/후진, 회전판, 출입문, 언덕·다리·계단, 마우스·키보드 조작, 카메라, 실내외 전환을 테스트. 기본 이동과 행마 방향의 관계, 판면 경계가 명확해질 때까지 12개 전체 지역에 동일 시스템을 복제하지 않는다.

### P3. 월드·에디터 데이터 정합
월드 지상 좌표·타일/미터 단위를 단일 정의로 고정. 마을/검문소 도로 연결성·회전판 간격·건물 접근성, 2D↔3D 배치 대칭을 자동/수동 검증. 시간선 그룹·분기·숨김·폐쇄·잔해 저장/불러오기 회귀 테스트. JSON 및 Godot 런타임 변환 규칙을 명시.

### P4. 스토리와 플레이 결합
세계관 공개 순서가 후반 진실을 앞당기지 않도록 하고, 분기 승진/기물 스킬/메가 체스트론/방향 전환 각성을 Godot 전투 시스템에 옮긴다. 기존 웹 알파는 참고 구현으로 두고 3D 런타임에 그대로 이식되었다고 전제하지 않는다.
