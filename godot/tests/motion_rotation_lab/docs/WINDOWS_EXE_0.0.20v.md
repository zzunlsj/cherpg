# CheRPG Motion Lab 0.0.20v — 카메라 기준 이동 복원 / 저속 떨림 보정

- Godot 4.7.2, Windows 64비트 독립 테스트장.
- 회사/제작자 파일 정보: **CheRPG** (디지털 코드서명은 별도).

## 0.0.19v 오류 원인

`pawn_player(2).cs`의 `inputVec`를 Godot 3D 수평 속도에 이식하면서 `Vector2(x,y)` 성분을 **월드 (X,Z)**에 바로 힘으로 적용한 경로가 있었습니다. 이 때문에 카메라의 바라보는 방향을 바꿔도 W가 기존 카메라 상대 전진으로 작동하지 않을 수 있었습니다.

## 수정

1. **카메라 기준 이동 복원:** Unity 원본의 WASD·방향키 입력 벡터는 입력상태로 유지하고, 실제 힘을 가하기 전에 `world_direction = camera_right*input.x + camera_forward*input.y`로 회전합니다. 카메라 `yaw`만 사용해 90° 탑뷰에서도 수평 전진 방향은 안정적입니다.
2. **저속 임계 속도 상향:** `SOURCE_MIN_SPEED`를 `0.1m/s → 0.6m/s`로 증가해 저속 흔들림 발생 구간에서 정지 마찰 분기가 우선 적용되도록 했습니다. 원본 C#의 0.1이 사용자 지시에 따라 변경된 유일한 임계 속도 값입니다.
3. `maxForce=20000`, 정지/운동 마찰 0.5/0.3, 입력 보간 10/s, Ctrl 달리기 최대 6m/s 및 Shift 웅크리기 등은 유지.
4. **한 번만 실제 물리 플레이 테스트를 수행**하도록 테스트용 자동 입력/엔진 물리 씬 기반 스크립트를 마련했습니다. 이번 요청 외에는 실행하지 않습니다.

## 현재 조작
- **WASD/방향키:** 카메라 기준 이동, **Ctrl:** 달리기·벽 붙잡기, **Shift:** 웅크리기.
- 등반 시 **Ctrl 유지:** 제자리 붙잡기, **Ctrl+W/S:** 벽 접선 위아래, **Ctrl+A/D:** 벽 접선 좌우. 카메라 시점 변화와 독립적.
- **F 홀드/놓기:** 앵커 공간 미리보기/설치·해제, **I:** 4m 논리 판면 이동 제한 ON/OFF (바닥 타일 표시 유지), **O:** 리셋, **Space:** 점프.

## 테스트 범위 / 한계
- 실제 Godot 씬에서 `InputEventKey`로 실제 입력을 시뮬레이션하고 `physics_frame`마다 본 플레이어를 움직이며 카메라 yaw 0°, 90°, 수직 탑뷰 90°, Ctrl 달리기, 입력 해제 후 저속 흔들림, Shift 웅크리기를 확인합니다.
- **이는 헤드리스 엔진 플레이 시뮬레이션**이며 사람이 Windows 화면으로 직접 조작하면서 모션의 시각 품질을 관찰하는 것과는 다릅니다. 자동 테스트 결과를 플레이 감각까지 검증했다고 확대 해석하지 않습니다.
- 일반 Godot collision과 물리적 충돌은 유지되고 4m 판면의 논리 이동 제한은 테스트 시 별도 토글합니다. 헤드리스 실험만 위해 본편 기능을 변경하지 않습니다.
